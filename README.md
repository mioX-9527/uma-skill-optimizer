# uma-skill-optimizer · 赛马娘技能PT规划器

> 按你的**实际 PT 预算**,基于 [mioX-9527/uma-race-sim](https://github.com/mioX-9527/uma-race-sim) 赛道模拟引擎,求**马身收益最大**的技能购买组合。

育成完一匹马后,技能购买界面里每项技能都有一个"实际价格"(hint/继承等折扣因号而异)。本工具以这些**实际价格**为输入,在预算内搜索购买组合——目标不是评价点,而是**比赛里能快多少个马身**(社区同类工具都只做评价点最大化,这里直接用赛道模拟做目标函数)。

**两种启动方式**:

1. **单文件网页版(免安装)** —— 双击根目录的 [`打开规划器.html`](打开规划器.html) 即可在浏览器打开(无需 Node)。在界面里手动添加候选技能、填上你号上看到的实际价格,一键算出推荐购买组合。
2. **桌面版(推荐,可自动抓取)** —— 双击 [`启动桌面版.bat`](启动桌面版.bat),把游戏停在技能购买界面后点「从模拟器读取」,会**自动连上模拟器逐屏抓取**:读出所有可学技能和你号上的实际价格、自动识别可进化技能(进化前后分别计价)、单双圈升级与金技能前置关系,结果直接填进规划器,不用手抄(需 Python 环境,首次运行自动装依赖)。

两种方式共用同一套优化器与界面;桌面版读完后也可以切回手动微调。

## 状态

v0.1(命令行 + 网页版 + 桌面版自动读取)已跑通:

- **网页版**(推荐):`npm run web` 或双击 `打开规划器.bat` → http://localhost:5183 。配置面板(赛道筛选/五维/跑法/适性/干劲/场地状态/天气/季节)、技能搜索添加(中/日/繁模糊匹配,pt 可逐条改)、一键计算(Worker 后台跑,不卡界面)、结果表格(推荐清单 + 未上车分类)、计划 JSON 导入导出(与 CLI 同格式)、配置自动保存在浏览器本地
- **从模拟器自动读取(桌面版)**:把游戏停在技能购买界面,一键读出技能名 + 你号上的实际价格 + PT 余额,自动识别进化(进化前后分别计价)、单双圈(◎ 自动补为独立候选)与金技能前置;见下文「自动读取实际 PT」
- **优化器**:贪心(按 马身/PT 效率,每装入一项重算全部候选边际)+ 交换局部搜索 + 预算回填。技能收益**非加性**(加速技能互相重叠、回体改变发动位置等),因此组合评估全部走真实模拟;44 候选全流程约 7 秒
- **引擎**:vendor 自 [mioX-9527/uma-race-sim](https://github.com/mioX-9527/uma-race-sim)(单马确定性期望模型;引擎/分析源码与技能/赛道数据通过 `npm run sync` 从本地 uma-race-sim 仓库同步)
- **绿技能已计入**:常时被动(如 博弈者、春初暖风、逆时针之鬼)并入起跑属性参与模拟,和普通技能一样按"马身/PT"竞争;带场地/赛场/季节/天气限制的绿技能只有在你选的场地/天气/季节下才生效(213 条绿技能里 164 条带限制)
- **马身口径**:与 uma-race-sim 的消融分析一致(Δ时间 × 末速 ÷ 2.5 米);区段随机取位技能(1118 条)按满足区段采样求**期望值**,与赛道模拟器的消融口径一致
- **输出**:推荐购买清单(按购入顺序,含 单独马身/集内边际 两列)、未购买技能及原因(超预算 / 不适配本配置 / 组合内无正收益 / 被更优组合挤出,含"再差多少 PT 能上车")、技能间交互差值如实展示
  - 「不适配本配置」指该技能在你当前的跑法/距离/场地下**根本不会发动**(如逃马限定的技能配先行),或效果尚未建模——这类技能单独收益恒为 0,但**不代表技能本身没用**,换配置再看

## 用法

**双击即用(免安装)**:根目录的 [`打开规划器.html`](打开规划器.html) 是单文件构建产物,双击直接在浏览器打开即可(无需 Node;此模式下优化器在主线程运行,计算时界面会短暂停顿)。

> **新电脑上**:下载本仓库后,`打开规划器.html` 双击即可直接使用(数据已全部内联);要用网页开发版或 CLI 需先 `npm install`;`npm run sync` 需要同机的 uma-race-sim 仓库(`--from <路径>` 可指定,不跑 sync 不影响使用)。

**网页版**(开发/流畅模式):

```bash
npm run web        # 或双击 打开规划器.bat
```

**命令行版**:

```bash
npm install
npm run sync        # 从 ../uma-race-sim 同步引擎与数据(可用 --from <路径> 指定)
npm test
npm run optimize -- --input examples/input.example.json [--budget 1000] [--out result.json]
```

> 以后模拟器(uma-race-sim)更新了,只需跑一次 `npm run sync`——引擎、技能/赛道数据和根目录的 打开规划器.html 会自动一起重新生成(未装依赖时只同步源码并提示)。

输入 JSON 格式(完整示例见 [`examples/input.example.json`](examples/input.example.json)):

```jsonc
{
  "course": "东京 草 2400m",          // 赛道名或 id(如 c10606)
  "budget": 1000,                     // PT 预算(硬约束)
  "runner": {                         // 面板(育成结果 + 因子 + 绿技能前提值)
    "stats": { "speed": 1200, "stamina": 1000, "power": 1100, "guts": 700, "wisdom": 900 },
    "tactic": "senko",                // nige/senko/sashi/oikomi
    "distanceAptitude": "A",
    "surfaceAptitude": "A",
    "motivation": "normal",
    "groundCondition": 0,             // 0良/1稍重/2重/3不良(会改体力消耗)
    "weather": 1,                     // 1晴/2阴/3雨/4雪(只影响「晴天◎」这类技能)
    "season": 1                       // 1春/2夏/3秋/4冬/5樱花(只影响「秋季优俊少女◎」这类技能)
  },
  "skills": [                         // 候选技能,pt 填游戏内实际显示价
    { "name": "中距离直线◎", "pt": 180 },  // 名称匹配(有歧义时请用 id)
    { "id": "901121", "pt": 120 }
  ]
}
```

注意事项:

- **pt 请填游戏内技能购买界面的实际显示价**(折扣因号而异);不填则用 `src/base-pt.json` 的兜底估算价并给出警告——兜底价不代表你的号的真实价格
- 绿技能(常时被动)已计入比赛模拟:收益来自起跑属性加成(过软上限 1200 与干劲),没有"发动位置";面板越高同类加成越挤,第二个同类绿技能往往明显不如第一个划算
- 带场地/赛场/距离/季节/天气/回转方向限制的技能(含大部分绿技能)只在你选的配置下生效;不满足时标为「不适配本配置」并写明原因(如「仅限秋季」「仅限东京赛场」)——把场地/天气/季节改对再算,才能看到它们的真实收益
- 依赖名次/人数的条件型被动(如「独行侠◎」)数据层未建模,会标为「不适配本配置」
- 依赖其他马娘的技能(数据层 `approx`)按期望近似,与 uma-race-sim 同一口径

## 工作原理

1. **无技能基准** → 逐候选单独模拟(单项马身)
2. **贪心装入**:每轮对全部在池候选重算"当前组合下的边际收益",选 边际/PT 最高者;收益重叠的技能(如两个加速技能)后装者的边际会被压低,自然避免重复堆同类技能
3. **交换局部搜索**:尝试"换出已选 + 换入未选",收益提升则交换并回填预算再贪心
4. **汇报**:最终组合的 leave-one-out 边际 + 未上车技能分类;"单项收益之和"与"实测总收益"同时给出,差值即技能间交互

## 自动读取实际 PT(已跑通)

目标:把游戏停在技能购买界面,**一键读出所有可学技能和它们在你号上的实际价格**,直接进优化器,不用手抄。

现状:已跑通并有真机实测 —— 一次 30 行的育成,43 屏 / 44 帧 / 约 100 秒,读出 44 条可购买技能 + PT 余额,价格与界面逐个一致。
除技能名与价格外还会自动识别:可进化关系(点开「进化 ⓘ」弹窗,进化前后分别计价)、
单双圈升级(◎ 作为独立候选自动补出,价格来自 BWIKI)、金技能的下位前置(避免重复计费)。

```bash
pip install -r app/requirements.txt     # pywebview + rapidocr + onnxruntime
双击 启动桌面版.bat                      # 开窗,里面会有「从模拟器读取」

# 或者用命令行
python -m app.cli devices               # 列出所有模拟器(带分辨率/前台应用),挑 --serial 用
python -m app.cli doctor                # 自检:adb / 分辨率 / 版式状态
python -m app.cli calibrate             # 出校准标注图(app/_debug/calib_lines.png)
python -m app.cli capture -o plan.json  # 全流程抓取(不填 --serial 自动挑开着赛马娘的那台)
```

前提:模拟器已启动、游戏停在技能购买列表、该模拟器开着 ADB 调试。
读不到时会直接告诉你原因(横屏 / 前台不是赛马娘 / 不在技能页),不会静默空转。

**同时开着好几个模拟器时**:窗口里「从模拟器读取」左边有个**设备下拉框**,每项显示
`序列号 · 机型 · 分辨率 · 前台应用`,前台是赛马娘的那台会标 `★ 赛马娘`,并默认选它;
选过的会记住。列表里没有你要的那台就点「刷新设备」(它会去扫 5555/7555/16384 等常见端口)。
**别指望 5555 一定是雷电** —— 实测过 5555 被 MuMu 占着,读出来是另一台模拟器的画面。

只读技能屏;**面板/跑法/赛道仍在网页里填**(那些在购买界面看不到)。
